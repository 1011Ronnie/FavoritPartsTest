# Поиск автозапчастей

Клиент для API «Проценка» Favorit Parts: поиск производителей по артикулу, затем исходных товаров и аналогов с предложениями по каждому складу.

Стек: React, JavaScript, Redux Toolkit / RTK Query, Vite, Bootstrap CSS.
Описание внешнего API сохранено в [wsprice.md](./wsprice.md).

## Запуск

Нужны Node.js 22.13+ в ветке 22 либо Node.js 24+ (рекомендуется Node.js 24 LTS) и npm. Ограничение Node.js учитывает требования ESLint 10.

```sh
npm ci
cp .env.example .env
```

Укажите действующий ключ клиента в `.env`:

```dotenv
VITE_API_KEY=ваш-ключ
```

```sh
npm run dev
```

Откройте адрес, напечатанный Vite (обычно `http://localhost:5173`). После изменения `.env` перезапустите сервер. Без ключа приложение показывает инструкцию и не отправляет запросы.

## Использование

1. Введите артикул: через 400 мс после последнего изменения появится список производителей.
2. Выберите производителя: приложение запросит исходные товары и аналоги.
3. В таблице каждое предложение склада занимает отдельную строку. Цена и остаток берутся только из `warehouses`; поле цены самого товара не используется. Код склада при отсутствии заменяется его ID.

Товары без предложений остаются в таблице с пометкой «Нет в наличии». Нулевые цены и остатки отображаются как `0`, отсутствующие значения — как `—`. Валюта в документации API не определена, поэтому символ валюты не добавляется.

При смене артикула старые результаты, выбранный бренд и ошибки сразу скрываются. Текущие запросы отменяются; при смене производителя отменяется запрос его предложений. Загрузка не блокирует поле ввода и переключение брендов. После ошибки доступна кнопка повтора.

## Стиль и организация кода

Проект использует JavaScript/JSX, поэтому TypeScript, `tsconfig`, `typescript-eslint` и фиктивная команда `typecheck` не добавляются. Проверка типов потребует отдельного решения о миграции или внедрении `checkJs`.

Форматирование выполняет Prettier, отдельно от ESLint. Версия formatter закреплена точно, чтобы результат совпадал локально и в CI. Единственная настройка поверх стандартных значений — одинарные кавычки в JavaScript. Отступ — два пробела; используются точки с запятой, завершающие запятые и стандартная ширина строки 80 символов. Общие настройки редакторов находятся в `.editorconfig`.

```sh
npm run format
npm run lint:fix
npm run format:check
npm run lint
```

После изменения импортов `lint:fix` может изменить переносы строк; при необходимости повторите `npm run format`. Проверки `format:check` и `lint` только читают исходники.

ESLint использует Flat Config, рекомендованные правила JavaScript, React Hooks и Vite Fast Refresh. Добавлены обязательные фигурные скобки, строгое сравнение, проверка дублей импортов и сортировка импортов. `eslint-config-prettier` отключает конфликтующие правила форматирования. Любое предупреждение делает проверку неуспешной. Browser globals разрешены в исходниках приложения, Node globals — только в конфигурации и тестовом коде. ESLint 10 учитывает JSX-ссылки, поэтому неиспользуемые компоненты выявляются без исключений для имён с заглавной буквы.

Единственный сортировщик импортов — `eslint-plugin-simple-import-sort`. Группы отделяются пустой строкой:

1. Side-effect imports, с сохранением их взаимного порядка. В частности, Bootstrap CSS остаётся перед локальными стилями.
2. React и React DOM.
3. Встроенные модули Node.js с префиксом `node:`.
4. Остальные внешние библиотеки.
5. Относительные импорты из родительских директорий.
6. Относительные импорты из текущей директории.

Aliases и barrel exports не вводятся: для текущего размера проекта достаточно относительных путей.

Файлы читаются сверху вниз: импорты, константы, основная экспортируемая логика, вспомогательные функции. В хуках сгруппированы state, запросы, refs, производные значения, обработчики и эффекты. Порядок хуков и зависимости эффектов сохраняются при style-refactoring. Условия загрузки, ошибки и пустого ответа оформляются ранними возвратами. Имена обработчиков начинаются с `handle`, callback props — с `on`, boolean-полей — с `is`/`has`/`can`/`should`.

`src/app` содержит store, `src/features/parts` — поиск, API, преобразование данных и сообщения ошибок этого сервиса, `src/components` — общие компоненты без зависимости от feature, `src/test` — тестовую инфраструктуру. Исходное описание API `wsprice.md`, lockfile, секреты и сгенерированные файлы исключены из форматирования.

GitHub Actions запускает `npm ci` и `npm run check` на push и pull request с Node.js 24. Проверки не требуют действующего ключа API и не отправляют изменения в репозиторий. Git hooks и дополнительные менеджеры пакетов не устанавливаются.
